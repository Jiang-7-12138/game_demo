# 积木与真实画面

这个版本把摄像头画面直接当作游戏画面。发光的白色小方块和无描边的白色通关门叠加在真实积木上；绿色、蓝色、红色和黄色仍由颜色识别赋予玩法含义，但正常画面不会显示识别后的几何方块。

## 启动

在本文件夹打开 PowerShell（Python 3.10/3.11）：

```powershell
python -m pip install -r requirements.txt
python game.py
```

启动后是纯白首页，默认显示黑色像素字“开始”，下方是“设置”。设置中可选择中文或英文；英文界面显示 START、SETTINGS 等对应文字。点击“开始”（也可按回车或空格）后只显示“连接中”，程序直接尝试连接 Logi 摄像头；只有尝试失败后才返回首页显示“未检测到摄像头”。程序优先尝试编号 1，也会自动尝试其他编号。游戏中按 `0` / `1` 可优先尝试指定编号，按 `Esc` 返回首页。点击“保存当前画面”会把正在显示的像素风游戏画面存为 `captures` 文件夹里的 PNG。

## 玩法

- `←` / `→` 移动，连续按两次 `↑` 可二段跳，空中不能跳第三次；落地后恢复两次跳跃。`↓` 快速下落，`R` 重开并重新随机放置通关门。
- 绿色是真实积木表面的可站立区域；蓝色河流每次进入扣 1 点生命；红色为空洞；黄色是可收集金币。小方块初始生命为 7，左上角“血条”后显示 7 根竖直红色像素长方形，受伤后相应格子变灰。落在真实画面中的底面不扣血。碰到**白色、无描边、无把手的长方形门**通关。门会随机出现在角色初始位置的另一侧，并优先放在积木色块范围之外；高度范围从底面一直延伸到画面顶部附近。同一关里位置固定，按 `R` 重开才重新抽取。
- 勾选“手势”后，手掌位于画面上半部的左/右侧可控制方向，食指与拇指捏合触发跳跃。手势需要另装 `mediapipe==0.10.18`；附带模型只用于找手部关键点，积木颜色不需要训练模型。

## 现场取景与识别

1. 固定摄像头，让积木正面和底排完整出现在画面里。默认识别整个摄像头画面；游戏底面是积木底排与白色底座接触的线。若重新摆放后角色悬空，请检查积木底排是否完整出现在画面中。背景尽量少出现同色物体，光照保持稳定。
2. 勾选“圈定积木区域”，直接在**游戏画面**上拖动，框住积木和底排，排除手部、桌面杂物。取消勾选后会恢复全画面识别，而不只是隐藏取景框。
3. 需要核对时勾选“显示碰撞层”：真实画面上会临时叠加半透明颜色，表示后台碰撞地图。确认后取消勾选，游戏显示像素化的实时摄像头画面、小方块、门，以及无底条的金币与生命像素 HUD。
4. 若颜色漏检或误检，可在 `config.json` 调整各色 HSV 阈值和 `min_area`，然后重新启动。OpenCV 色相 H 范围为 0–179，红色可以跨 179/0。

后台把色块分割结果缩成约 4×4 摄像头像素一个单元，再做短时间置信度与进出阈值处理。这会减少灯光和色块边缘一两帧的抖动，同时保留转盘转动时的形状变化。底面由绿色、蓝色和红色地形的最低边缘确定，黄色金币与桌面反光不会推动底面。低分辨率碰撞图、角色和门都使用同一套摄像头像素坐标，显示时一起等比放大，因此角色会直接在实物画面里跑跳。被完全遮挡的积木部分依然无法从单个摄像头还原。
